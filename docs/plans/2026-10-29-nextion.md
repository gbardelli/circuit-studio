# Programmable touchscreen

Implement the real Nextion NX3224T028 resistive 320×240 UART HMI as a protocol-level peripheral. Firmware draws with ASCII commands terminated by FF FF FF. `sendxy=1` enables the documented 0x67 coordinate packets for press and release. The Arduino handles these packets in its compiled sketch.

The screen uses physical power, common ground and crossed UART nets. Baud rate and 8N1 must match. The Mega exposes all four hardware USARTs, with paced receive queues so multi-byte packets survive. Unwired and unpowered devices cannot communicate. UART electrical waveforms are not synthesized.

Supported commands: `cls`, `fill`, `draw`, `line`, `xstr`, `sendxy`, `bkcmd`, `dim`, `baud`, `get` for supported system variables and `sendme`. Unsupported commands return protocol errors. `xstr` supports a solid background or no background; font IDs use approximate simulator fonts. This model does not upload Nextion Editor .HMI/.TFT resources, images, page components or execute embedded Nextion scripts. The inspector states that limitation.

The standalone template uses Mega Serial1 and toggles D13 from the touchscreen. The elevator template keeps all destination memory, request lockout, comparison and direction control in commercial logic ICs. Mega D22–D32 monitor those ICs; the touchscreen drives D33–D36 as open-drain hall-call inputs. Physical cabin and hall buttons remain usable.

Validation includes exact packet bytes, framing, invalid commands, power resets, UART2/3, disconnected power/ground/RX/TX, baud mismatch, GPIO response and touchscreen elevator calls. The screen is checked in the browser after firmware compilation.
